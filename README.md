# lol-mate-stats

英雄联盟选人阶段队友战绩面板：进入选人阶段后，自动读取 5 名队友最近 10 场对局，计算 **近期评分** 和 **坑指数**，在本地网页里一眼看完。

- 不需要 Riot API Key
- 支持国服 / 外服（数据来自本机客户端 LCU 接口）
- 选人阶段显示 5 名队友；对局中显示双方 10 名玩家，5 张卡片一排
- 面板只监听 `127.0.0.1`；LCU 数据只读，缓存、历史存档和 AI 分析写入你配置的 MySQL
- 附带模拟数据模式，没有客户端也能预览界面

```
┌─ 队友战绩 ─────────────────────────────── 选人阶段 ─┐
│ [中单] Faker的小粉丝     78 S   近10场 5胜5负        │
│   KDA 3.4 · 参团 61% · 分伤 720 · 伤害占比 28%      │
│   ⚠ 坑指数 52  分均伤害 310（参考 ≥390）            │
└────────────────────────────────────────────────────┘
```

## 快速开始

要求：Node.js >= 22.13，Windows（国服客户端 / Riot 客户端均可）。

```bash
npm install

npm start          # 启动面板，监听选人阶段，自动打开浏览器
npm run once       # 不启动网页，直接在终端输出当前选人阶段 / 对局中的队友数据
npm run demo       # 无客户端，使用模拟数据预览界面（含一名“新手”示例）
npm run scan -- "召唤师名称"   # 查询指定召唤师最近战绩
npm run doctor     # 诊断：客户端连接、接口、大区、战绩是否可用
```

默认地址：<http://127.0.0.1:51730>

进入选人阶段后会自动刷新；也可以按 `R` 或点击「刷新」强制重新拉取。

页面右上角有「查玩家 名字#TAG」输入框，可以直接查询任意玩家的近期战绩；也可以直接打开
`http://127.0.0.1:51730/?player=游戏名%23TAG` 自动查询。命令行等价入口：`npm run scan -- "游戏名#TAG"`。

进入对局后会自动切换为本局 10 名玩家（己方 5 人 + 敌方 5 人），5 张卡片一排；卡片内容与选人阶段一致（近期评分、坑指数、最近对局），并额外显示本局的实时 KDA、补刀、等级、视野、装备价值、参团率和分均数据，以及当前出装。敌方卡片带「敌方」标记。

所有战绩都**按当前模式统计**：大乱斗只看大乱斗、单双排只看单双排、灵活/匹配/竞技场同理；同模式不够场次时会自动扩大候选范围继续往前翻。近期胜率、伤害、参团等指标都基于同一模式，避免拿排位数据评价大乱斗。

每张卡片底部有「查看最近 N 场战绩」按钮，点开可以看到完整对局列表（胜负、英雄、KDA、评分、时长、时间、对局类型和标签）；本人卡片点击右上角的英雄头像或名字即可查看该英雄战绩，选人阶段按当前选择的英雄、对局详情按本局使用的英雄，直接打开自己在该英雄上的战绩列表。对局详情的页签右侧显示时间、时长和胜负，下面一行是双方团队汇总（击杀、助攻、总伤害、总承伤、总治疗、总经济，每项用上下两条颜色横线对比）。弹窗右上角的「更新」会绕过报告、召唤师信息和段位缓存，重新拉取当前这名玩家的战绩并同步卡片。工具栏的「最近一局」会跳过列表，直接打开我最近一场对局的详情；「我的战绩」会合并客户端最近 30 场和远程 MySQL 历史存档，**每场都显示评分**，点「加载更早的战绩」（或直接滚动到列表底部）会继续往前翻页：优先读 MySQL 存档，不够时再通过客户端 / Player Platform Edge 拉取更早的对局，客户端不可用时自动只读 MySQL 存档，可以一直看到客户端提供的最后一页；点列表里的任意一场，会展开该局双方 10 名玩家的近期战绩卡片，读取过程中会显示 `x/10` 进度和已用时间。对局详情里有两个页签，默认打开「本局详情」：它把这一局的真实数据（KDA、补刀、经济、伤害、承伤、治疗、视野）做成卡片，并且**每张卡片上都有两个重叠的六边形**，六个角直接标出参团、经济、KDA、承伤、伤害、治疗的具体数值（伤害/承伤带占比），对比该玩家和本局 10 人平均；「近期战绩」是 10 人的近期评分卡片（含场均治疗）。右上角的「✨ AI 分析」会用弹窗流式生成本局复盘。结果会保存到 MySQL 的 `ai_analyses` 表，之后再次打开同一局会直接读取，不会重复请求；弹窗里的「重新分析」会强制重新请求并覆盖保存。进入对局后，工具栏还会出现「✨ AI 分析」，它会根据我的英雄、双方阵容和当前装备，生成出装、技能加点和打法建议，并按本局会话保存到 `ai_live_analyses` 表。对局结束后，这条“比赛中的建议”会自动关联到该局，在「本局详情」的 AI 弹窗里通过「对局中建议」页签查看。工具栏的「英雄排名」会按平均单场评分给我的英雄排序，并可按「全部 / 召唤师峡谷 / 极地大乱斗 / 斗魂竞技场」切换模式；每个英雄显示场次、胜率、最高分和最低分，点击英雄可直接打开该英雄的战绩列表。统计会合并特殊模式里的 60000+ 英雄 ID（如 60067 与 67 视为同一英雄），并排除训练模式。

对局列表会额外标记「重开」「自己小坑 / 自己坑 / 自己巨坑 / 自己逃跑」「队友逃跑 / 对手逃跑」「队友小坑 / 队友坑 / 队友巨坑」「敌方小坑 / 敌方坑 / 敌方巨坑」：重开根据 early surrender 字段或 5 分钟内结束的对局判断，只出现在「我的战绩」总列表；逃跑没有官方字段，使用「时长 ≥ 8 分钟且伤害/经济/补刀/参团/视野同时异常」做保守推断，只要出现击杀/助攻、承伤或治疗等活跃痕迹就只判坑、不判逃跑；但如果伤害、承伤、治疗、参团都远低于队友且死亡很少，即使有少量击杀/助攻，也会判逃跑（典型是长时间挂机后出来收残局）。坑按本局表现分分档（< 32 小坑、< 25 坑、< 18 巨坑）。每局评分最高的胜方玩家标 `MVP`，评分最高的负方玩家标 `SVP`，战绩列表和对局详情都会显示，重开不计。玩家卡片的「查看最近 N 场战绩」会跳过重开并自动补足 N 场正常对局。以上均为数据推断，仅供参考。

### 常用参数

| 参数 | 说明 |
| --- | --- |
| `-p, --port <n>` | 网页端口，默认 `51730`（固定 5 位端口；被旧面板占用会自动结束旧进程，被其它程序占用会报错） |
| `-r, --recent <n>` | 每位玩家分析的场次，默认 `10`，范围 1-30 |
| `--no-open` | 不自动打开浏览器 |
| `--json` | `once` / `scan` 输出 JSON |
| `--quiet` | 减少日志 |
| `--token <token>` | 手动指定 LCU remoting token |

### 找不到客户端时

1. 确认客户端已经**登录并进入大厅**（只启动到登录页时接口不可用）。
2. 运行 `npm run doctor` 查看具体是哪一步失败。
3. 国服 / WeGame 环境下 `lockfile` 可能是 0 字节、进程命令行又读不到，此时工具会退回到客户端日志（`LeagueClientUx.log`）里解析端口与 token；安装目录会从 `RiotClientInstalls.json` 自动识别。若仍失败，可以手动指定连接信息：

```powershell
# 端口和 token 在客户端进程命令行里：--app-port=xxxxx --remoting-auth-token=xxxxx
# 也可以在 LeagueClientUx.log 里搜 --app-port / --remoting-auth-token
$env:LCU_PORT="xxxxx"
$env:LCU_PASSWORD="xxxxx"
npm run once
```

## 怎么判断一个队友是不是“坑”？

只看“伤害占比”是不准的：全队都被打崩时，20% 的伤害占比也可能只是 4K 总伤害。因此本项目同时看 **绝对值 + 相对值 + 多场稳定性**。

### 1. 绝对伤害（重点）

把「整场伤害」换算成 **分均伤害（DPM）**，再和同位置参考值比较：

| 位置 | 参考值 | 偏低（×0.65） | 严重偏低（×0.42） |
| --- | ---: | ---: | ---: |
| 上单 | 550 /min | < 358 | < 231 |
| 打野 | 500 /min | < 325 | < 210 |
| 中单 | 650 /min | < 423 | < 273 |
| ADC | 700 /min | < 455 | < 294 |
| 辅助 | 380 /min | < 247 | < 160 |
| 大乱斗 | 850 /min | < 553 | < 357 |
| 竞技场 | 900 /min | < 585 | < 378 |

举例：一局 25 分钟只打了 4K 伤害 → 160/min，无论什么位置都属于**严重偏低**；30 分钟 12K 伤害 → 400/min，中单/ADC 仍然偏低。

### 2. 其他硬指标

每个位置分别判断：

- **分均补刀**：中单 6.8、ADC 7.5、上单 6.5、打野 5.2 为参考；低于参考的 60% 记不达标，低于 38% 记严重（辅助和大乱斗不判补刀）。
- **参团率**：低于 45% 记不达标，低于 33% 记严重。伤害高但从不参团，同样算坑。
- **场均死亡**：≥ 7.5 场均已偏高，≥ 9 单场记严重。
- **分均视野**：辅助 1.6、打野 1.05 为参考，低于 60% 记不达标，低于 38% 记严重。
- **胜率**：只作为加分项（近 5 场以上且胜率 ≤ 35%），不会因为输得多就直接判坑。

### 3. 单场“坑度” → 坑指数

每场比赛按上面的超标情况累计权重：

- 伤害严重偏低 +1.8，偏低 +1.0
- 补刀严重偏低 +1.2，偏低 +0.6
- 死亡 ≥ 9 +1.0，≥ 7 +0.5
- 参团 < 33% +1.0，< 45% +0.5
- 视野严重偏低 +0.8，偏低 +0.4

单场权重 **≥ 2.0 记为“明显不达标”**，**≥ 3.2 记为“严重不达标”**。

```
坑指数 = 100 × (0.6 × 不达标场次比例 + 0.4 × 严重不达标场次比例)
        + 场均评分低于 55（每低 1 分 +0.5，最多 +12）
        + 场均死亡 ≥ 7.5          (+5)
        + 近期胜率 ≤ 35%（≥5场）  (+4)
        + 分均伤害低于参考 60%    (+4)
        + 账号等级 < 40 且已偏低  (+8)
```

| 坑指数 | 等级 | 界面标签 |
| ---: | --- | --- |
| 0-19 | 低 | 不显示 |
| 20-39 | 中 | `有点坑` |
| 40-59 | 高 | `偏坑` |
| ≥ 60 | 严重 | `坑` |

**新手提示**：账号等级 < 50，且数据明显偏低时，额外显示 `疑似新手`。
注意低等级也可能是小号/代练，所以它只是“提示”，真正决定结论的仍是战绩数据。

**样本保护**：不足 3 场时坑指数最高只到 45，避免“两把没打好就被判死刑”。

### 4. 不会因为什么判坑

- **输赢本身**：败方 SVP 不会因为输了就被标坑；赢了但 4K 伤害仍可能被标坑。
- **KDA 好看**：只刷人头、不参团、不打伤害，仍会被其他指标拉高风险。
- **辅助补刀少**：辅助不参与补刀判定；坦克/辅助更看参团、视野和承伤。
- **大乱斗**：使用独立基准（伤害更高、不判补刀）。
- **单场波动**：结论来自最近 10 场的**比例**，一把打崩不会直接变成“坑”，除非同时触发多个严重项。

**重开不算一场正常对局**：5 分钟内结束或带 early surrender 的对局不计入胜率、连胜、评分、英雄池和坑指数，系统会自动跳过并往前补足 10 场正常对局；重开标记只保留在「我的战绩」总列表里。

### 5. 关于“评分”

评分和坑指数是两套视角：

```text
KDA百分位 / 参团百分位 / 输出百分位 / 承伤百分位 / 治疗百分位
  = 本局 10 名玩家中的相对排名（0–1）

绝对分 = 5 × (
    0.9764
  + KDA权重 × KDA百分位
  + 参团权重 × 参团百分位
  + 输出权重 × 输出百分位
  + 承伤权重 × 承伤百分位
  + 治疗权重 × 治疗百分位
)

单场评分 = 100 × (绝对分 / 100) ^ 0.7

近期评分 = 按 0.92^i 加权平均（越近权重越高）
```

权重按英雄类型区分：

| 类型 | KDA | 参团 | 输出 | 承伤 | 治疗 |
| --- | ---: | ---: | ---: | ---: | ---: |
| carry（法师/ADC/刺客） | 5.4 | 1.2 | 7.8 | 2.3 | 0.01 |
| support（软辅/治疗） | 5.0 | 3.5 | 3.0 | 3.5 | 1.7 |
| tank（坦克/硬辅） | 4.0 | 2.5 | 3.5 | 6.0 | 0.7 |
| fighter（战士） | 4.8 | 2.2 | 5.0 | 4.5 | 0.2 |
| default（未知） | 5.40 | 1.28 | 6.79 | 3.22 | 0.02 |

琴女、星妈、娜美、露露、猫咪、风女、卡尔玛、萨勒芬妮等按 `support`；火男、法师、ADC 按 `carry`；坦克/硬辅按 `tank`；战士按 `fighter`。

- 评分：0-100，越高越好；`S ≥ 78`、`A ≥ 68`、`B ≥ 58`、`C ≥ 48`、`D < 48`
- 坑指数：0-100，越高越像坑
- 两者可以同时高/低：评分高说明数据好，坑指数低说明没有明显短板

**评分是“局内百分位”，不是“全服百分位”**。它衡量的是同一局 10 名玩家中的相对表现：各项都在中游时约 58 分，五项都靠前时约 92 分，五项都垫底时约 12 分。默认权重来自 40 个掌上英雄联盟（掌盟）评分样本的拟合，再按英雄类型调整，并做 0.7 次幂的单调校准（10→20、40→53、70→78、90→93），不是官方公式。

伤害占比 < 6%、参团率 < 35% 且死亡 ≥ 10 的极端局，评分会直接封顶 12 分，归入“巨坑”，避免软辅/坦克权重把明显没打出作用的局托到 25 分以上。伤害占比 < 5%、承伤占比 < 8%、治疗占比 < 10%、参团率 < 30% 且死亡 ≤ 5 的“避战保 KDA”局同样封顶 12 分，即使 KDA 好看也不会被当成正常表现。

历史对局的评分可以用下面的命令重算（可重复执行）：

```powershell
# 全量重算
npm run db:recompute-scores

# 只重算最近几天（分阶段预览）
npm run db:recompute-scores -- --since 2026-10-31

# 把某天之前的对局恢复成旧版全局权重
npm run db:recompute-scores -- --before 2026-10-31 --old

# 只重算一局
npm run db:recompute-scores -- --game 9061816747

# 限制并发（默认 4，范围 1-16；MySQL 用异步并发，不是 worker 线程）
npm run db:recompute-scores -- --concurrency 8
```

**只统计当前模式**：打大乱斗时只取最近的大乱斗对局，打单双排时只取单双排，打灵活/匹配/竞技场同理。为了避免同模式样本太少，会额外多取候选场次再筛选。

### 6. 关于“疑似挂机”

官方 LCU 战绩接口**没有挂机标记**，这里只做保守推断：单场时长 ≥ 8 分钟，且伤害、经济、补刀、参团、视野同时极低（或 0/0/0）才记一场“疑似挂机”。

- 当前分析的场次中 ≥ 3 场，或 ≥ 2 场且占比 ≥ 25%：显示 `常挂机`
- 只有 1 场：显示 `疑似挂机`

宁可漏判也不把被针对、辅助或新手误标成挂机，所以它只是提示，不是官方处罚记录。

> 所有判定的参考值都是“经验基准”，目的是快速识别明显异常，不是裁判文书。有人打法特殊、阵容特殊、被针对，数据都会变形，请结合对局内容判断。本工具不读取聊天记录，也无法获取官方的挂机/故意送处罚记录。

## 工作原理

```
英雄联盟客户端 (LCU)
   │  lockfile / 进程命令行 / LeagueClientUx.log → 端口 + token
   ▼
Node 服务 (127.0.0.1)
   │  轮询 + WebSocket 事件监听阶段（选人 / 对局中）
   │  /lol-champ-select/v1/session   → 队友列表
   │  /lol-summoner/v1/summoners/:id → 名字、等级、头像
   │  /lol-match-history/v1/...      → 最近对局（含详细数据）
   │  /lol-ranked/v1/...             → 段位（可选，失败自动忽略）
   ▼
游戏内 Live Client Data API (127.0.0.1:2999，无需认证)
   │  /liveclientdata/allgamedata  → 本局 10 人、英雄、KDA/补刀/视野/等级/装备
   ▼
评分 / 坑指数 / 实时指标 → 本地网页 (SSE 实时推送)
```

- 全部走 `https://127.0.0.1:<客户端端口>`，使用客户端自带的 Basic Auth，不需要登录 Riot 开发者账号。
- 服务只绑定 `127.0.0.1`，不开放局域网/公网。
- 头像、英雄图标通过 `/api/asset` 从客户端本地资源读取，无网络请求（demo 模式用彩色首字占位）；读到的图标会缓存到磁盘，客户端关闭后仍可显示。
- 装备图标会在第一次读取装备数据后，于后台预存到 `LOL_MATE_DATA_DIR`（默认 Windows「文档/lol-mate-stats」）下的 `assets/`（约 800+ 个、几 MB），之后打开「本局详情」不再依赖客户端在线。
- 实时数据只有 Live Client Data API 提供：全员 KDA、补刀、视野分、等级、装备、召唤师技能、符文和复活倒计时；本人还能拿到当前血量/蓝量、攻击/法强/护甲/魔抗/技能急速、实际金币和技能等级；本局事件（击杀、推塔、小龙、大龙等）会作为实时 AI 的节奏参考。官方接口**不返回**其他玩家的伤害、承伤和金币，伤害、承伤、治疗要等对局结算后从战绩接口读取（「本局详情」里的六边形用的就是结算数据）。
- 其他玩家的报告缓存会保留到出现新对局为止（每 5 分钟最多检查一次；对局详情本身不会变）；自己的战绩每次都实时读取，不吃报告缓存。右上角「清缓存」可随时手动清空。
- 报告、召唤师、段位、英雄列表和对局存档都写入远程 MySQL（`mysql2`，默认库名 `lol_mate_stats`），启动时自动建表。连接参数见 `.env.example`；连接失败时面板仍可用，只是不保存数据和历史存档，并会在 30 秒后自动重试。「我的战绩」会用客户端完整对局实时补算评分和坑/逃跑标记，所以没配置 MySQL 也能看到最近 30 场的标记，只是看不到更早的存档。
- 从旧版 SQLite 升级时，本地 `cache.db` 不会自动导入；执行一次 `npm run db:migrate` 即可把旧数据搬到 MySQL。
- 默认使用 `lol_mate_user@你的服务器IP:3306` 直连。若不想暴露 3306，可改用 SSH 隧道（见上文）或只允许固定 IP 访问，并给该用户只授予 `lol_mate_stats.*` 权限。
- 读取过的完整对局会永久写入 `matches` / `match_participants` 表，包含双方 10 人的英雄、KDA、补刀、经济、伤害、承伤、视野、评分和标签；打开「我的战绩」时会在后台补齐尚未归档的对局。对局原始 JSON 不落盘。
- 「清缓存」只清空报告/召唤师/段位等缓存表，不会删除历史对局存档。
- 客户端重启或更换端口会自动重新发现；事件订阅断开时会退化为轮询。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/snapshot` | 当前快照（JSON） |
| GET | `/api/stream` | SSE，实时推送快照 |
| POST | `/api/refresh` | 强制刷新战绩 |
| GET | `/api/scan?name=游戏名%23TAG` | 查询任意玩家最近战绩 |
| POST | `/api/player/refresh?summonerId=...&queueId=...&mode=SR` | 强制更新单个玩家的战绩（绕过缓存） |
| GET | `/api/me/matches?recent=30&offset=0` | 当前账号最近对局列表（含每场评分），`offset` 用于继续往前翻页 |
| GET | `/api/archive/matches?limit=100&offset=0` | 历史存档，可用 `puuid` 指定玩家 |
| GET | `/api/archive/champions?mode=ARAM&minGames=1` | 按英雄统计平均单场评分并排序，`mode` 支持 `SR` / `ARAM` / `ARENA`，可用 `puuid` 指定玩家 |
| GET | `/api/match/:gameId` | 某场对局双方 10 人的近期战绩（加 `refresh=1` 强制更新） |
| GET | `/api/match/:gameId/stream` | 同上，NDJSON 流式返回进度和结果 |
| GET | `/api/match/:gameId/ai` | 读取该局已保存的 AI 分析 |
| POST | `/api/match/:gameId/ai` | 对某场对局做 AI 复盘，NDJSON 流式返回并保存到数据库（需配置 `LOL_MATE_AI_API_KEY`） |
| GET | `/api/live/ai` | 读取当前进行中对局已保存的实时 AI 建议 |
| POST | `/api/live/ai` | 对进行中的对局做 AI 出装/技能/打法建议，NDJSON 流式返回并按本局会话保存 |
| GET | `/api/ai/status` | AI 是否已配置、当前模型 |
| POST | `/api/cache/clear` | 手动清空报告缓存（保留历史对局） |
| GET | `/api/asset?path=...` | 代理客户端图片资源 |
| GET | `/api/health` | 健康检查 |

## 常见问题

**战绩为空 / 只显示部分队友？**
新号、隐藏战绩、或该大区接口临时不可用。9 级以下账号通常没有对局记录。`npm run doctor` 的「战绩接口」可以确认。

`npm run doctor` 还会额外检查客户端侧的查询链路：

- `战绩 edge`：客户端实际使用的查询地址（来自客户端日志）以及连通性
- `失败记录`：最近几个客户端会话里战绩请求的失败次数、最后一次失败时间
- `最后错误`：客户端日志记录的上游错误原文

如果 edge 可达但请求全是 5xx，说明是客户端/腾讯侧的查询服务超时，和本机网络无关；只有部分玩家失败时，是那几名玩家所在分片超时，稍后刷新即可。

**游戏进行中看不到本局玩家？**
对局数据来自 Live Client Data API（`127.0.0.1:2999`），加载界面阶段还没就绪，进入游戏后几秒内会自动出现。若一直空白，用 `npm run doctor` 确认当前阶段是 `InProgress`；仍失败时检查是否有防火墙拦截本地 2999 端口。

**对局中能看到伤害、伤害占比、承伤吗？**
不能。Live Client Data API 只提供每名玩家的 KDA、补刀、视野分、等级和装备，不提供伤害、承伤和金币（只有当前玩家自己的实时金币）。对局中只显示这些能拿到的实时指标，经济用已购装备总价近似。伤害/承伤/治疗会在**对局结束后**由战绩接口补齐，出现在「我的战绩 → 本局详情」的六边形和指标里。

**国服能用吗？**
可以。国服客户端同样是 LCU 接口，`npm run doctor` 能读到阶段和战绩即可。若客户端由 WeGame 启动，进程名仍是 `LeagueClientUx.exe`。

**会影响游戏或封号吗？**
只读本地客户端接口，不注入游戏进程、不修改客户端文件、不自动操作对局。和常见战绩查询工具原理相同。仍请自行评估风险，不要将端口/token 暴露给他人。

**评分和 OP.GG 一样吗？**
不一样。这里的参考值针对“快速识别队友状态”调过，更强调分均伤害、参团和稳定性；不包含对局内视野布置、控制时长等更细的数据。

**为什么有人评分高但坑指数也高？**
评分看“数据完成度”，坑指数看“是否明显低于同位置基准”。比如刷了很多伤害但场均死亡 10 次、参团 25%，可能评分不低但坑指数偏高。
