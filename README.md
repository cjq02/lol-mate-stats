# lol-mate-stats

英雄联盟选人阶段队友战绩面板：进入选人阶段后，自动读取 5 名队友最近 10 场对局，计算 **近期评分** 和 **坑指数**，在本地网页里一眼看完。

- 不需要 Riot API Key
- 支持国服 / 外服（数据来自本机客户端 LCU 接口）
- 选人阶段显示 5 名队友；对局中显示双方 10 名玩家，5 张卡片一排
- 面板只监听 `127.0.0.1`；LCU 数据只读，缓存、历史存档和 AI 分析写入你配置的 MySQL
- 附带模拟数据模式，没有客户端也能预览界面

```
┌─ 队友战绩 ─────────────────────────────── 选人阶段 ─┐
│ [中单] Faker的小粉丝     78 S   近10场 5胜5负        │
│   KDA 3.4 · 参团 61% · 分伤 720 · 伤害占比 28%      │
│   ⚠ 坑指数 52  分均伤害 310（参考 ≥390）            │
└────────────────────────────────────────────────────┘
```

## 快速开始

要求：Node.js >= 22.13，Windows（国服客户端 / Riot 客户端均可）。

```bash
npm install

npm start          # 启动面板，监听选人阶段；已有面板页签时刷新该页签，没有才打开浏览器
npm run once       # 不启动网页，直接在终端输出当前选人阶段 / 对局中的队友数据
npm run demo       # 无客户端，使用模拟数据预览界面（含一名“新手”示例）
npm run scan -- "召唤师名称"   # 查询指定召唤师最近战绩
npm run doctor     # 诊断：客户端连接、接口、大区、战绩是否可用
```

默认地址：<http://127.0.0.1:51730>

重复启动时，如果浏览器里还开着面板页签，会等它自动重连后直接刷新原页签，不会再新开一个；只有检测不到已打开的面板时才打开浏览器。想强制新开页签可以用 `--no-open` 后手动访问上面的地址。

进入选人阶段后会自动刷新；也可以按 `R` 或点击「刷新」强制重新拉取。

页面右上角有「查玩家 名字#TAG」输入框，可以直接查询任意玩家的近期战绩；也可以直接打开
`http://127.0.0.1:51730/?player=游戏名%23TAG` 自动查询。命令行等价入口：`npm run scan -- "游戏名#TAG"`。

进入对局后会自动切换为本局 10 名玩家（己方 5 人 + 敌方 5 人），5 张卡片一排；卡片内容与选人阶段一致（近期评分、坑指数、最近对局），并额外显示本局的实时 KDA、补刀、等级、视野、装备价值、参团率和分均数据，以及当前出装。敌方卡片带「敌方」标记。对局阶段的卡片默认只露出「坑场次」和「展开其余指标」按钮，实时/近期指标点一下再展开，避免卡片过高。

所有战绩都**按当前模式统计**：大乱斗只看大乱斗、单双排只看单双排、灵活/匹配/竞技场同理；同模式不够场次时会自动扩大候选范围继续往前翻。近期胜率、伤害、参团等指标都基于同一模式，避免拿排位数据评价大乱斗。

卡片还会显示当前英雄的历史熟练度（场次 / 胜率 / 均分 / 最高分）、与个人长期基线相比的状态（`高于自身 +1.2σ` / `低于自身 -1.4σ`），以及最近 10 场评分走势；当前分配位置与近期主玩位置不一致时会标出 `主玩中单` 这类提示。个人基线需要存档里至少有 10 场，样本不足时自动隐藏。

**大乱斗选人阶段**会在顶部列出当前分配到的英雄和替补席英雄，并按整体胜率从高到低排序（没有样本的英雄排在最后，当前英雄仍会标注）：卡片上方显示整体/我的胜率，英雄名和「我的平均单场评分」在下方（只在我玩过的英雄上显示），使用场次放在悬停提示里；点击可直接打开我在该英雄上的战绩列表。整体胜率来自本地 MySQL 存档里所有玩家的大乱斗对局，没配置数据库或样本不足时显示 `-` / `未使用`。

每张卡片底部有「查看最近 N 场战绩」按钮，点开可以看到完整对局列表（胜负、英雄、KDA、评分、时长、时间、对局类型和标签），每场同样会显示 MVP/SVP、坑和逃跑标签，评分左侧还会标出该局 10 人中的评分排名（同分并列，悬停可看完整名次）；列表上方会按当前已加载的对局汇总场次、胜率、平均评分、平均排名、MVP/SVP 次数和坑场次，并画出一条评分分段长条（80+ / 70–79 / 60–69 / 50–59 / 40–49 / 30–39 / 30 以下，颜色和列表里的单场评分一致），标出每段的场次和占比；再上方有「近 10 场 / 近 20 场 / 近 50 场 / 近 100 场 / 近 200 场 / 全部」范围页签，切换时会自动继续翻页补足场次；列表底部可以继续加载更早的存档战绩。本人卡片点头像下方的「战绩」即可查看该英雄战绩（点头像本身弹的是英雄说明），选人阶段按当前选择的英雄、对局详情按本局使用的英雄，直接打开自己在该英雄上的战绩列表。对局详情的页签右侧显示时间、时长和胜负，下面一行是双方团队汇总（击杀、助攻、总伤害、总承伤、总治疗、总经济，每项用上下两条颜色横线对比）。每张玩家卡片的评分环左上角还会标出本局 10 人中的评分排名（同分并列，悬停可看完整名次），点击评分环会弹出本局评分标准（该英雄的本局位置、官方分类、主副定位、KDA / 参团 / 输出 / 承伤 / 治疗五项权重占比、命中的加减分项和短板扣分规则），再次点击或点击弹窗外收起，不额外占用卡片高度；选人阶段、对局中和「近期战绩」里的玩家卡片会在评分下方单独一行突出显示最近 N 场的平均评分排名（「平均排名 #X.X」），数字按名次着色，悬停可看参与统计的场次；至少要有 3 场人数一致的正常对局才显示，样本不足或旧存档人数不一致时会隐藏平均排名。弹窗右上角的「更新」会绕过报告、召唤师信息和段位缓存，重新拉取当前这名玩家的战绩并同步卡片。工具栏的「最近一局」会跳过列表，直接打开我最近一场对局的详情；对局刚结束、客户端战绩列表还没同步时，会先用结算界面数据存档并显示这一局，不必等待客户端缓存刷新；「我的战绩」会合并客户端最近 30 场和远程 MySQL 历史存档，**每场都显示评分**，并默认打开「极地大乱斗」页签，可以按「全部 / 召唤师峡谷 / 极地大乱斗 / 斗魂竞技场」切换模式，页签切换后胜率统计和往前翻页都会跟随当前模式；召唤师峡谷下还有「全部 / 排位 / 匹配 / 人机 / 快速模式 / 训练」子页签；点「加载更早的战绩」（或直接滚动到列表底部）会继续往前翻页：优先读 MySQL 存档，不够时再通过客户端 / Player Platform Edge 拉取更早的对局，客户端不可用时自动只读 MySQL 存档，可以一直看到客户端提供的最后一页；点列表里的任意一场，会先立即展示本局双方 10 人的详情，随后在后台继续加载 10 名玩家的近期战绩；加载进度显示在弹窗右上角，加载完成后自动切换到完整的近期战绩数据。完整详情会持久写入 MySQL 的 `match_details`，以后再次打开同一局会直接读数据库，服务重启后也不会重新抓取；点「更新」可以强制重新拉取。缓存版本变化时旧详情会自动失效。对局详情里有两个页签，默认打开「本局详情」：它把这一局的真实数据（KDA、补刀、经济、伤害、承伤、治疗、视野）做成卡片，并且**每张卡片上都有两个重叠的六边形**，六个角直接标出参团、经济、KDA、承伤、伤害、治疗的具体数值（伤害/承伤带占比），六边形按各自阵营单独归一化、对比该玩家和本方队伍平均，角上的排名则把双方 10 人放在一起计算；如果结算接口返回 `timeline`，卡片还会显示每 10 分钟的分均经济和对位补刀差，并标出「对线落后，中后期追回」这类节奏；历史对局没有客户端分组字段，系统会根据 10 名玩家最近战绩里「同队同局」的次数推断开黑，至少 2 场同队才会在敌我双方卡片上标「开黑 N 人」，避免把深夜随机重排误判成开黑；「近期战绩」是 10 人的近期评分卡片（含场均治疗）。右上角的「⏱ 时间线」会按阵亡事件把对局切成一条条命，显示每条命的存活时长、KDA、补刀/金币增量、等级，并在每条命里按时间列出完整击杀/助攻事件（相关英雄只显示头像，悬停可看名字，“我”的头像带金色描边，例如“击杀 [头像] · 助攻 [头像][头像]”“[我的头像][头像] 助攻 [头像] 击杀 [头像]”）和阵亡信息；弹窗顶部提供 10 名玩家的页签，默认选中「我」，其余按己方、敌方排列，点任意页签即可查看该玩家自己的时间线和对位统计；上方汇总用单行紧凑展示，并按每个对方英雄统计“击杀我 / 助攻杀我 / 我击杀 / 我助攻”的次数；时间线里还会用曲线展示双方每分钟经济差，并在曲线上标出推塔时间。对局详情顶部的逃跑提示会附带判定依据，例如“存活期间原地不动 4 分 13 秒”。时间线来自客户端 `game-timelines` 接口，第一次打开实时读取并写入 MySQL 的 `match_timelines`，之后客户端关闭也能直接命中存档。官方接口不提供每条命的伤害/承伤，弹窗只显示整局总伤害/承伤，并按条命给出平均值，明确标注伤害无法精确拆分。右上角的「✨ AI 分析」会用弹窗流式生成本局复盘，并自动读取同一条时间线，把每条命的存活、KDA、补刀/金币、死亡对象、经济差曲线和推塔节奏一起交给模型分析；每条命伤害仍不可用，模型只会引用整局伤害/承伤，不会编造。结果会保存到 MySQL 的 `ai_analyses` 表，之后再次打开同一局会直接读取，不会重复请求；弹窗里的「重新分析」会强制重新请求并覆盖保存。选人阶段工具栏会出现「✨ AI 选人」，它会根据我方已选英雄、我的英雄池和（大乱斗）替补席，给出留人/换人、符文、召唤师技能和出装建议；敌方阵容在选人阶段未知，AI 会明确说明。选人建议不写入数据库，换英雄或重新进入选人后会重新生成。进入对局后，工具栏还会出现「✨ AI 分析」，它会根据我的英雄、双方阵容和当前装备，生成出装、技能加点和打法建议，并按本局会话保存到 `ai_live_analyses` 表。对局结束后，这条“比赛中的建议”会自动关联到该局，在「本局详情」的 AI 弹窗里通过「对局中建议」页签查看。工具栏的「英雄排名」会按平均单场评分给我的英雄排序，默认打开「极地大乱斗」，并可按「全部 / 召唤师峡谷 / 极地大乱斗 / 斗魂竞技场」切换模式，还可以按平均分、场次、胜率、最高分或熟练度排序；每个英雄显示场次、胜率、综合熟练度、平均单场排名和最高/最低分，熟练度由场次经验、胜率、均分和最高分计算，样本越少置信度越低。统计会合并特殊模式里的 60000+ 英雄 ID（如 60067 与 67 视为同一英雄），并排除训练模式。点击英雄进入的战绩列表由后端按「英雄 + 当前模式」直接查询，每页 20 场，滚动到底部或点「加载更早的战绩」继续翻页。工具栏的「时间统计」会把历史对局按本地时间统计成多个维度：最近 30 天、最近 12 周、最近 12 个月、一天内每 2 小时一段、周一至周日，以及上单 / 打野 / 中单 / ADC / 辅助等位置和坦克 / 战士 / 输出 / 辅助等英雄类型，每个维度都会统计场次、胜率、平均单场评分、队友坑/逃跑率和自己坑率。弹窗顶部的「胜率 / 评分」页签可以切换统计口径：胜率口径在每一行直接标出场次、胜负、平均评分和最常遇到坑的时段；评分口径显示每个时段的平均单场评分、最高/最低分和评分样本场次，并标出评分最高和最低的时段。默认按天展示最近 30 天，也可以切换按周 / 按月 / 按时段 / 按星期 / 按位置 / 按类型；模式默认跟随当前对局，也可以切换「全部 / 召唤师峡谷 / 极地大乱斗 / 斗魂竞技场」。没有历史存档时会退回客户端最近 100 场。

对局列表会额外标记「重开」「自己小坑 / 自己很坑 / 自己巨坑 / 自己逃跑」「队友逃跑 / 对手逃跑」「队友小坑 / 队友很坑 / 队友巨坑」「敌方小坑 / 敌方很坑 / 敌方巨坑」：重开根据 early surrender 字段或 5 分钟内结束的对局判断，只出现在「我的战绩」总列表；逃跑没有官方字段，使用「时长 ≥ 8 分钟且伤害/经济/补刀/参团/视野同时异常」做保守推断，只要出现击杀/助攻、承伤或治疗等活跃痕迹就只判坑、不判逃跑；但如果伤害、承伤、治疗、参团都远低于队友且死亡很少，即使有少量击杀/助攻，也会判逃跑（典型是长时间挂机后出来收残局）。如果该局已保存时间线，且存活期间连续没有补刀、也没有击杀/助攻/阵亡的最长时间不到 5 分钟，说明玩家在持续发育或参战，此时只判坑、不判逃跑（大乱斗的金币、经验和等级即使挂机也会增长，所以不作为活动信号）；但如果时间线显示存活期间连续原地不动达到 3 分钟，即使前期有击杀/助攻，也会判逃跑（典型是后期停在基地挂机），这条证据不受 8 分钟时长门槛限制，7 分钟速推局里同样生效。分段挂机也会被识别：即使单次空闲都不到 5 分钟，只要时间线里累计没有补刀和战斗的时间达到 5 分钟、且占对局 35% 以上，同样判逃跑。旧缓存详情打开时会按当前规则重新复核逃跑标记。坑按本局表现分分档（< 30 小坑、< 25 很坑、< 20 巨坑）。近期卡片会显示「坑场次 X / N」，统计最近 N 场里单场评分 < 30 的小坑 / 很坑 / 巨坑场次。每局评分最高的胜方玩家标 `MVP`，评分最高的负方玩家标 `SVP`，战绩列表和对局详情都会显示，重开不计。玩家卡片的「查看最近 N 场战绩」会跳过重开并自动补足 N 场正常对局。以上均为数据推断，仅供参考。逃跑和坑标签可以同时出现（例如“队友逃跑”和“队友巨坑”）；战绩列表里只有「自己逃跑」使用单独的实心高亮徽章；「队友逃跑 / 对手逃跑」留在标签行里，用橙色或玫红色描边小胶囊稍微加强；MVP/SVP 使用实心金/银徽章，坑使用描边徽章。对局详情顶部的逃跑提示和玩家卡片里的「逃跑」也会用高亮样式。

评分颜色按 80 / 70 / 60 / 50 / 40 / 30 分档：≥80 绿色、70–79 青色、60–69 宝蓝色、50–59 黄色、40–49 橙色、30–39 浅红色、<30 深红色；`0/0/0`、`0/1/0` 这类几乎没有参与对局的场次显示灰色，没有评分时显示深灰。

### 常用参数

| 参数 | 说明 |
| --- | --- |
| `-p, --port <n>` | 网页端口，默认 `51730`（固定 5 位端口；被旧面板占用会自动结束旧进程，被其它程序占用会报错） |
| `-r, --recent <n>` | 每位玩家分析的场次，默认 `10`，范围 1-30 |
| `--no-open` | 不自动打开浏览器 |
| `--json` | `once` / `scan` 输出 JSON |
| `--quiet` | 减少日志 |
| `--token <token>` | 手动指定 LCU remoting token |

环境变量支持写在项目根目录的 `.env` 里（复制 `.env.example` 后修改），真实的系统环境变量优先：

```dotenv
# 远程 MySQL（启动时自动建表）
LOL_MATE_MYSQL_HOST=你的服务器IP
LOL_MATE_MYSQL_PORT=3306
LOL_MATE_MYSQL_USER=lol_mate_user
LOL_MATE_MYSQL_PASSWORD=你的密码
LOL_MATE_MYSQL_DATABASE=lol_mate_stats

# 本地数据目录（装备图标、导入用的旧 cache.db）
# LOL_MATE_DATA_DIR=E:\lol-mate-stats

# 可选
PORT=51730
RECENT_GAMES=10

# AI 分析（本局详情里的「AI 分析」按钮）
# 在 https://opencode.ai/console 创建 OpenCode Go API Key 后粘贴
LOL_MATE_AI_API_KEY=你的_API_Key
```

如果 MySQL 只允许本机或内网访问，可以走 SSH 隧道，应用侧只改 `HOST` / `PORT`：

```powershell
ssh -N -L 13306:127.0.0.1:3306 cjq.tencent
```

```dotenv
LOL_MATE_MYSQL_HOST=127.0.0.1
LOL_MATE_MYSQL_PORT=13306
```

从旧版 SQLite 升级时，先停掉面板，再执行一次导入（可重复执行，相同主键会覆盖）：

```powershell
npm run db:migrate
# 或指定其它 cache.db
npm run db:migrate -- "E:\Users\你\Documents\lol-mate-stats\cache.db"
```

AI 分析默认使用 OpenCode Go 的 `deepseek-v4.1-flash`，也可以覆盖：

```dotenv
LOL_MATE_AI_BASE_URL=https://opencode.ai/inference/go/openai/v1
LOL_MATE_AI_MODEL=deepseek-v4.1-flash
# 临时关掉 AI 按钮的请求能力
LOL_MATE_AI_DISABLED=1
```

也兼容 `OPENCODE_GO_API_KEY` / `OPENCODE_API_KEY` 作为 Key 的别名。配置后重启面板：选人阶段点工具栏的「✨ AI 选人」可以生成选人、符文和出装建议；进入对局后点「✨ AI 分析」会带上实时的每条命时间线（存活、KDA、补刀、等级、击杀者）；打开任意一场对局的「本局详情」，点右上角的「✨ AI 分析」即可流式生成赛后复盘。

对局中的 AI 弹窗支持**定向追问**：底部有「现在最该做的 3 件事」「下一件装备出什么」「对面谁最肥，怎么针对」等快捷问题，也可以自己输入。追问只回答当前问题，不再重刷整篇复盘，回答会**增量追加**在原分析下方；弹窗右侧按顺序列出问题节点，点击可跳到对应回答。追问不覆盖已经保存的整局分析，关闭弹窗再打开仍保留当前这局的追问记录。

AI 会先按当前模式校验装备可用性：大乱斗不会推荐守护天使、黑暗封印、梅贾的窃魂卷、共生鞋鱼，也不会建议回城补给、插眼反眼或争夺小龙/大龙。出装会按敌方阵容给分支：战士至少给半肉和全肉两套，坦克会给心之钢成长流和功能防装流，并说明敌方多 AD、多 AP、高回复或高爆发时怎么换。心之钢在极地大乱斗**没有被禁用**，之前不推荐是因为提示词没有显式提到它；现在已加入可选装备和坦克分支。

也兼容 `LCU_PORT`、`LCU_PASSWORD`、`LOL_LOCKFILE`、`LOL_INSTALL_DIR`。旧版的 `LOL_MATE_DB` / `LOL_MATE_CACHE` 已不再使用。

### 找不到客户端时

2. 运行 `npm run doctor` 查看具体是哪一步失败。
3. 国服 / WeGame 环境下 `lockfile` 可能是 0 字节、进程命令行又读不到，此时工具会退回到客户端日志（`LeagueClientUx.log`）里解析端口与 token；安装目录会从 `RiotClientInstalls.json` 自动识别。若仍失败，可以手动指定连接信息：

# 也可以在 LeagueClientUx.log 里搜 --app-port / --remoting-auth-token
$env:LCU_PORT="xxxxx"

## 怎么判断一个队友是不是“坑”？

只看“伤害占比”是不准的：全队都被打崩时，20% 的伤害占比也可能只是 4K 总伤害。因此本项目同时看 **绝对值 + 相对值 + 多场稳定性**。

### 1. 绝对伤害（重点）

把「整场伤害」换算成 **分均伤害（DPM）**，再和同位置参考值比较：

| 位置 | 参考值 | 偏低（×0.65） | 严重偏低（×0.42） |
| --- | ---: | ---: | ---: |
| 上单 | 550 /min | < 358 | < 231 |
| 打野 | 500 /min | < 325 | < 210 |
| 中单 | 650 /min | < 423 | < 273 |
| ADC | 700 /min | < 455 | < 294 |
| 辅助 | 380 /min | < 247 | < 160 |
| 大乱斗 | 850 /min | < 553 | < 357 |
| 竞技场 | 900 /min | < 585 | < 378 |

举例：一局 25 分钟只打了 4K 伤害 → 160/min，无论什么位置都属于**严重偏低**；30 分钟 12K 伤害 → 400/min，中单/ADC 仍然偏低。

### 2. 其他硬指标

每个位置分别判断：

- **分均补刀**：中单 6.8、ADC 7.5、上单 6.5、打野 5.2 为参考；低于参考的 60% 记不达标，低于 38% 记严重（辅助和大乱斗不判补刀）。
- **参团率**：低于 45% 记不达标，低于 33% 记严重。伤害高但从不参团，同样算坑。
- **场均死亡**：≥ 7.5 场均已偏高，≥ 9 单场记严重。
- **分均视野**：辅助 1.6、打野 1.05 为参考，低于 60% 记不达标，低于 38% 记严重。
- **胜率**：只作为加分项（近 5 场以上且胜率 ≤ 35%），不会因为输得多就直接判坑。

### 3. 单场“坑度” → 坑指数

每场比赛按上面的超标情况累计权重：

- 伤害严重偏低 +1.8，偏低 +1.0
- 补刀严重偏低 +1.2，偏低 +0.6
- 死亡 ≥ 9 +1.0，≥ 7 +0.5
- 参团 < 33% +1.0，< 45% +0.5
- 视野严重偏低 +0.8，偏低 +0.4

单场权重 **≥ 2.0 记为“明显不达标”**，**≥ 3.2 记为“严重不达标”**。

```
坑指数 = 100 × (0.6 × 不达标场次比例 + 0.4 × 严重不达标场次比例)
        + 场均评分低于 55（每低 1 分 +0.5，最多 +12）
        + 场均死亡 ≥ 7.5          (+5)
        + 近期胜率 ≤ 35%（≥5场）  (+4)
        + 分均伤害低于参考 60%    (+4)
        + 账号等级 < 40 且已偏低  (+8)
```

| 坑指数 | 等级 | 界面标签 |
| ---: | --- | --- |
| 0-19 | 低 | 不显示 |
| 20-39 | 中 | `有点坑` |
| 40-59 | 高 | `偏坑` |
| ≥ 60 | 严重 | `很坑` |

**新手提示**：账号等级 < 50，且数据明显偏低时，额外显示 `疑似新手`。
注意低等级也可能是小号/代练，所以它只是“提示”，真正决定结论的仍是战绩数据。

**样本保护**：不足 3 场时坑指数最高只到 45，避免“两把没打好就被判死刑”。

### 4. 不会因为什么判坑

- **输赢本身**：败方 SVP 不会因为输了就被标坑；赢了但 4K 伤害仍可能被标坑。
- **KDA 好看**：只刷人头、不参团、不打伤害，仍会被其他指标拉高风险。
- **辅助补刀少**：辅助不参与补刀判定；坦克/辅助更看参团、视野和承伤。
- **大乱斗**：使用独立基准（伤害更高、不判补刀）。
- **单场波动**：结论来自最近 10 场的**比例**，一把打崩不会直接变成“坑”，除非同时触发多个严重项。

**重开不算一场正常对局**：5 分钟内结束或带 early surrender 的对局不计入胜率、连胜、评分、英雄池和坑指数，系统会自动跳过并往前补足 10 场正常对局；重开标记只保留在「我的战绩」总列表里。

### 5. 关于“评分”

评分和坑指数是两套视角：

```text
KDA百分位 / 参团百分位 / 输出百分位 / 承伤百分位 / 治疗百分位
  = 本局 10 名玩家中的相对排名（0–1）

绝对分 = 5 × (
    0.9764
  + KDA权重 × KDA百分位
  + 参团权重 × 参团百分位
  + 输出权重 × 输出百分位
  + 承伤权重 × 承伤百分位
  + 治疗权重 × 治疗百分位
)

单场评分 = 绝对分 + 加减分 - 短板扣分

近期评分 = 按 0.92^i 加权平均（越近权重越高）
```

权重按英雄主 / 副定位区分：

| 类型 | KDA | 参团 | 输出 | 承伤 | 治疗 |
| --- | ---: | ---: | ---: | ---: | ---: |
| carry（法师/ADC/刺客） | 5.4 | 1.2 | 7.8 | 2.3 | 0.01 |
| support（软辅/治疗） | 5.0 | 3.5 | 3.0 | 3.5 | 1.7 |
| tank（坦克/硬辅） | 2.8 | 3.2 | 2.0 | 7.8 | 0.9 |
| fighter（战士） | 4.8 | 2.2 | 5.0 | 4.5 | 0.2 |
| default（未知） | 5.40 | 1.28 | 6.79 | 3.22 | 0.02 |

英雄定位来自客户端本地 `champions/{id}.json` 的 `roles` 字段（官方分类：`mage` / `marksman` / `assassin` / `fighter` / `tank` / `support`，一个英雄可以有多项），映射到 4 个评分模板：法师、射手、刺客归 `carry`，坦克归 `tank`，战士归 `fighter`，辅助归 `support`。

一个英雄有多项官方分类时按 **主定位 + 副定位** 处理：主定位占 70%，副定位占 30%，上表是主定位的原始权重，有副定位时线性混合。例如：

- 刀妹 `fighter + assassin`：70% 战士 + 30% 输出，刺客不会再被丢掉
- 猴子 `fighter + tank`：70% 战士 + 30% 坦克，承伤比纯战士更值钱
- VN `marksman + assassin`：两项都归 `carry`，仍按纯输出评分

官方原始分类会一起保留在定位表里（`classes`），用于“含刺客”这类细分规则；评分权重仍按映射后的 4 个模板计算。

短板扣分和核心指标只看主定位。辅助模板不做副定位：官方 Support 标签也包含火男、泽拉斯、慧这类输出型辅助，混入治疗/承伤权重会系统性压低他们的评分。

定位表由脚本生成，新增英雄或官方分类调整后运行 `npm run build && node scripts/generate-champion-roles.mjs` 重新生成。

坦克/硬辅不再把输出占比当成主要指标：承伤和参团权重最高、输出权重最低，高承伤高参团的慎/奥恩不会因为输出占比低而被输出位稳压。

输出位的承伤低于本局中位时按中位计算：伤害打出来了、承伤又低，通常是站位好，不能因为承伤全场最低就按“垫底”扣分；只有承伤明显高于中位才继续加分。坦克/战士不受这条限制，承伤是他们的本职工作。

**短板扣分**在绝对分之后生效：

- 参团率 < 35%，且输出占比 < 8%（carry / fighter / default）、承伤占比 < 18%（tank）或治疗占比 < 10%（support）：再扣 6 分。
- 三项核心指标（carry：KDA / 参团 / 输出；fighter：KDA / 输出 / 承伤；tank：KDA / 参团 / 承伤；support：KDA / 参团 / 治疗）中有 2 项处于本局后 20%：扣 4 分；3 项都处于后 20%：扣 8 分。核心指标按主定位选，副定位不改变短板规则。
- 扣完仍按 `< 30 小坑`、`< 25 很坑`、`< 20 巨坑` 判定。

**加减分项**（累计封顶 `+4 / -4`）：

- 经济转化，只对 `carry` / `fighter`：
  - 伤害占比 ÷ 经济占比 ≥ 1.3 且伤害占比 ≥ 20%：`+1.5`（低经济高输出）
  - 经济占比 ≥ 20% 且伤害占比 ÷ 经济占比 ≤ 0.85：`-2`（吃资源没打出伤害）
- 人头 / 死亡，按位置区分：
  - 含官方 `assassin` 分类的英雄（劫、阿卡丽、刀妹、剑圣等），优先于主定位的击杀门槛：
    - ≥ 15 杀 → `+1.5`
    - ≥ 20 杀且参团率 ≥ 55% → `+2.5`
    - ≥ 25 杀且参团率 ≥ 60% → `+3.5`
    - 不按死亡数打折（大乱斗死亡天然偏高）
  - `carry`：≥ 18 杀 → `+1.5`；死亡占比 ≥ 25% 且 ≥ 8 死 → `-1.5`
  - `fighter`：≥ 15 杀 → `+1`；死亡占比 ≥ 32% 且 ≥ 12 死 → `-1`
  - `tank`：不拿人头分；死亡占比 ≥ 30% 且 ≥ 13 死 → `-1`
  - `support`：不拿人头分；死亡占比 ≥ 25% 且 ≥ 8 死 → `-1`
- 挂机/逃跑判定成立时，单场评分直接封顶 `12` 分；原本低于 12 的不再上调。

例如螳螂 `9/6/3`、参团 32.4%、输出占比 7.2%，绝对分 18.0，触发“参团 + 输出双低”的 -6 分后变成 12.0，判为“巨坑”。

- 评分：0-100，越高越好；`S ≥ 78`、`A ≥ 68`、`B ≥ 58`、`C ≥ 48`、`D < 48`
- 坑指数：0-100，越高越像坑
- 两者可以同时高/低：评分高说明数据好，坑指数低说明没有明显短板

**评分是“局内百分位”，不是“全服百分位”**。它衡量的是同一局 10 名玩家中的相对表现：各项都在中游时约 47 分，五项都靠前时约 88 分，五项都垫底时约 5 分。默认权重来自 40 个掌上英雄联盟（掌盟）评分样本的拟合，再按英雄类型调整，不做额外的曲线托底（避免把 30 分的局抬到 40 以上），最后扣除短板分，不是官方公式。对局详情里的六边形排名和卡片左上角名次按双方 10 人计算，平均排名只统计至少 3 场人数一致（通常是 10 人）的正常对局，样本不足时不显示。

伤害占比 < 6%、参团率 < 35% 且死亡 ≥ 10 的极端局，评分会直接封顶 12 分，归入“巨坑”，避免软辅/坦克权重把明显没打出作用的局托到正常范围。伤害占比 < 5%、承伤占比 < 8%、治疗占比 < 10%、参团率 < 30% 且死亡 ≤ 5 的“避战保 KDA”局同样封顶 12 分，即使 KDA 好看也不会被当成正常表现。

历史对局的评分可以用下面的命令重算（可重复执行）：

```powershell
# 全量重算
npm run db:recompute-scores

# 只重算最近几天（分阶段预览）
npm run db:recompute-scores -- --since 2026-10-31

# 把某天之前的对局恢复成旧版全局权重（不应用短板减分）
npm run db:recompute-scores -- --before 2026-10-31 --old

# 只重算一局
npm run db:recompute-scores -- --game 9061816747

# 限制并发（默认 4，范围 1-16；MySQL 用异步并发，不是 worker 线程）
npm run db:recompute-scores -- --concurrency 8
```

重算完成后会同时清空报告缓存和对局详情缓存；旧详情里保存的评分和坑档不会继续沿用，下一次打开会按新口径重新生成。

**只统计当前模式**：打大乱斗时只取最近的大乱斗对局，打单双排时只取单双排，打灵活/匹配/竞技场同理。为了避免同模式样本太少，会额外多取候选场次再筛选。

对局时间线可以手动回填最近缺失的场次（平均约 146 KB/场）：

```powershell
npm run db:backfill-timelines                    # 补最近 100 场缺时间线的对局
npm run db:backfill-timelines -- --limit 200     # 多补一些
npm run db:backfill-timelines -- --dry-run       # 只列出待回填对局
npm run db:backfill-timelines -- --game 9082565891 --force  # 重拉单局
```

面板启动后也会在后台自动补最近 100 场缺时间线的对局；回填后会同时更新参与者表的挂机时长，历史战绩列表里的逃跑标签会更准。5 分钟以内的重开局会跳过。

### 6. 关于“疑似挂机”

官方 LCU 战绩接口**没有挂机标记**，这里只做保守推断：单场时长 ≥ 8 分钟，且伤害、经济、补刀、参团、视野同时极低（或 0/0/0）才记一场“疑似挂机”。如果结算接口提供 `timeline`，连续 5 分钟以上几乎没有经济/经验增长的局也会判为疑似挂机，用来识别“前 10 分钟正常、中段掉线”的情况。如果该局已经保存了按每条命切分的时间线，系统还会统计存活期间连续没有补刀、也没有击杀/助攻/阵亡的最长时间：不到 5 分钟时说明玩家一直在发育或参战，会撤销逃跑判定；这个信号只用于排除误判，不会单独新增逃跑。但如果存活期间连续原地不动达到 3 分钟（位移不超过 250 个地图单位，且没有补刀和战斗事件），说明玩家后期停在基地或原地挂机，即使前期有击杀/助攻也会直接判逃跑；这条证据与对局时长无关，7 分钟速推局里同样生效。另外，单次空闲都不到 5 分钟、但累计空闲达到 5 分钟且占对局 35% 以上时，按分段挂机处理——大乱斗里正常玩家几乎每分钟都会有补刀或战斗。大乱斗的金币、经验和等级即使挂机也会增长，所以不参与这些判断。旧存档没有这列数据时仍按原有规则判断。

- 当前分析的场次中 ≥ 3 场，或 ≥ 2 场且占比 ≥ 25%：显示 `常挂机`
- 只有 1 场：显示 `疑似挂机`

宁可漏判也不把被针对、辅助或新手误标成挂机，所以它只是提示，不是官方处罚记录。

> 所有判定的参考值都是“经验基准”，目的是快速识别明显异常，不是裁判文书。有人打法特殊、阵容特殊、被针对，数据都会变形，请结合对局内容判断。本工具不读取聊天记录，也无法获取官方的挂机/故意送处罚记录。

## 工作原理

```
英雄联盟客户端 (LCU)
   │  lockfile / 进程命令行 / LeagueClientUx.log → 端口 + token
   ▼
Node 服务 (127.0.0.1)
   │  轮询 + WebSocket 事件监听阶段（选人 / 对局中）
   │  /lol-champ-select/v1/session   → 队友列表
   │  /lol-summoner/v1/summoners/:id → 名字、等级、头像
   │  /lol-match-history/v1/...      → 最近对局（含详细数据）
   │  /lol-ranked/v1/...             → 段位（可选，失败自动忽略）
   ▼
游戏内 Live Client Data API (127.0.0.1:2999，无需认证)
   │  /liveclientdata/allgamedata  → 本局 10 人、英雄、KDA/补刀/视野/等级/装备
   ▼
评分 / 坑指数 / 实时指标 → 本地网页 (SSE 实时推送)
```

- 全部走 `https://127.0.0.1:<客户端端口>`，使用客户端自带的 Basic Auth，不需要登录 Riot 开发者账号。
- 服务只绑定 `127.0.0.1`，不开放局域网/公网。
- 头像、英雄图标通过 `/api/asset` 从客户端本地资源读取，无网络请求（demo 模式用彩色首字占位）；读到的图标会缓存到磁盘，客户端关闭后仍可显示。
- 装备图标会在第一次读取装备数据后，于后台预存到 `LOL_MATE_DATA_DIR`（默认 Windows「文档/lol-mate-stats」）下的 `assets/`（约 800+ 个、几 MB），之后打开「本局详情」不再依赖客户端在线。
- 点击英雄头像会弹出英雄名、官方角色、玩法标签、被动和 QWER 技能（名称 + 描述 + 图标 + 每级冷却和消耗，取客户端每级系数数组的前 5 项；无消耗的技能显示「无消耗」），点击装备图标会弹出装备名称、描述和价格；再点一次或点弹窗外收起。头像本身带其他点击动作时（本人英雄的「战绩」按钮、替补席卡片、时间线玩家页签、英雄排名行、对局列表行）保持原点击行为，不弹说明。这些数据同样读客户端本地资源，英雄详情会落盘、装备描述去掉富文本标签后只在点击时按需加载，不撑大卡片和图标接口。
- 实时数据只有 Live Client Data API 提供：全员 KDA、补刀、视野分、等级、装备、召唤师技能、符文和复活倒计时；本人还能拿到当前血量/蓝量、攻击/法强/护甲/魔抗/技能急速、实际金币和技能等级；本局事件（击杀、推塔、小龙、大龙等）会作为实时 AI 的节奏参考。官方接口**不返回**其他玩家的伤害、承伤和金币，伤害、承伤、治疗要等对局结算后从战绩接口读取（「本局详情」里的六边形用的就是结算数据）。对局中还会读取 gameflow 的分组信息，同队玩家共享 `teamParticipantId` 时会在敌我双方卡片上标出「开黑 N 人」。
- 其他玩家的报告缓存会保留到出现新对局为止（每 5 分钟最多检查一次）；出现新对局时只增量补那一场，不重拉最近 N 场；对局结束后会自动预热并保存本局详情，回到大厅再打开可直接命中缓存。自己的战绩每次都实时读取，不吃报告缓存；对局中如果客户端只返回少量对局或战绩接口不可用，会自动从 MySQL 存档补齐最近 N 场，避免样本过少。存档补齐对双方 10 名玩家都生效，卡片和点开后的战绩列表使用同一份样本。
- 历史战绩列表默认按「对局时间 + gameId」做游标分页，翻到很后面也不会因为大 `offset` 变慢；`match_participants` 上有 `(puuid, champion_id)` 复合索引，英雄战绩和英雄排名查询会直接命中。
- 报告、召唤师、段位、英雄列表和对局存档都写入远程 MySQL（`mysql2`，默认库名 `lol_mate_stats`），启动时自动建表，并按 `meta.schemaVersion` 顺序执行版本化迁移（补列、补索引）。连接参数见 `.env.example`；连接失败时面板仍可用，只是不保存数据和历史存档，并会在 30 秒后自动重试。「我的战绩」会用客户端完整对局实时补算评分和坑/逃跑标记，所以没配置 MySQL 也能看到最近 30 场的标记，只是看不到更早的存档。
- 从旧版 SQLite 升级时，本地 `cache.db` 不会自动导入；执行一次 `npm run db:migrate` 即可把旧数据搬到 MySQL。
- 默认使用 `lol_mate_user@你的服务器IP:3306` 直连。若不想暴露 3306，可改用 SSH 隧道（见上文）或只允许固定 IP 访问，并给该用户只授予 `lol_mate_stats.*` 权限。
- 读取过的完整对局会永久写入 `matches` / `match_participants` 表，包含双方 10 人的英雄、KDA、补刀、经济、伤害、承伤、视野、评分和标签；打开「我的战绩」时会在后台补齐尚未归档的对局。对局原始 JSON 不落盘。
- 客户端重启或更换端口会自动重新发现；事件订阅断开时会退化为轮询。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/snapshot` | 当前快照（JSON） |
| GET | `/api/stream` | SSE，实时推送快照 |
| POST | `/api/refresh` | 强制刷新战绩 |
| GET | `/api/scan?name=游戏名%23TAG` | 查询任意玩家最近战绩 |
| POST | `/api/player/refresh?summonerId=...&queueId=...&mode=SR` | 强制更新单个玩家的战绩（绕过缓存） |
| GET | `/api/me/matches?recent=30&offset=0` | 当前账号最近对局列表（含每场评分），`offset` 用于继续往前翻页 |
| GET | `/api/archive/matches?limit=100&offset=0` | 历史存档，可用 `puuid` 指定玩家；传 `championId`、`mode` 或 `group` 可按英雄 / 模式 / 统计组查询 |
| GET | `/api/archive/champions?mode=ARAM&minGames=1` | 按英雄统计平均单场评分并排序，`mode` 支持 `SR` / `ARAM` / `ARENA`，可用 `puuid` 指定玩家 |
| GET | `/api/archive/time-stats?mode=ARAM` | 按本地时间统计最近 30 天、最近 12 周、最近 12 个月、时段、星期、英雄位置和英雄类型的胜率、平均单场评分与队友坑/逃跑率，`mode` 支持 `SR` / `ARAM` / `ARENA` |
| GET | `/api/archive/record?queueId=450&mode=ARAM` | 按模式 / 统计组 / 英雄统计长期胜率 |
| GET | `/api/match/:gameId` | 某场对局双方 10 人的近期战绩（加 `refresh=1` 强制更新） |

| GET | `/api/match/:gameId/timeline` | 本局时间线（按阵亡切分每条命）；首次读客户端并写入 `match_timelines`，之后命中存档 |
| GET | `/api/match/:gameId/ai` | 读取该局已保存的 AI 分析 |
| POST | `/api/match/:gameId/ai` | 对某场对局做 AI 复盘，NDJSON 流式返回并保存到数据库（需配置 `LOL_MATE_AI_API_KEY`） |
| GET | `/api/live/ai` | 读取当前进行中对局已保存的实时 AI 建议 |
| POST | `/api/live/ai` | 对进行中的对局做 AI 出装/技能/打法建议，NDJSON 流式返回并按本局会话保存；请求体传 `{"question":"..."}` 时改为定向追问，只返回该问题的回答、不覆盖已保存分析 |
| GET | `/api/ai/status` | AI 是否已配置、当前模型 |
| POST | `/api/cache/clear` | 手动清空报告缓存（保留历史对局） |
| GET | `/api/asset?path=...` | 代理客户端图片资源 |
| GET | `/api/champion-info?ids=1,2` | 英雄角色标签、被动和技能（点击英雄头像用，最多 40 个 id） |
| GET | `/api/item-details` | 装备名称、描述和价格（点击装备图标用，描述已转成纯文本） |
| GET | `/api/health` | 健康检查 |

## 常见问题

**战绩为空 / 只显示部分队友？**
新号、隐藏战绩、或该大区接口临时不可用。9 级以下账号通常没有对局记录。`npm run doctor` 的「战绩接口」可以确认。

`npm run doctor` 还会额外检查客户端侧的查询链路：

- `战绩 edge`：客户端实际使用的查询地址（来自客户端日志）以及连通性
- `失败记录`：最近几个客户端会话里战绩请求的失败次数、最后一次失败时间
- `最后错误`：客户端日志记录的上游错误原文

如果 edge 可达但请求全是 5xx，说明是客户端/腾讯侧的查询服务超时，和本机网络无关；只有部分玩家失败时，是那几名玩家所在分片超时，稍后刷新即可。

**游戏进行中看不到本局玩家？**
对局数据来自 Live Client Data API（`127.0.0.1:2999`），加载界面阶段还没就绪，进入游戏后几秒内会自动出现。若一直空白，用 `npm run doctor` 确认当前阶段是 `InProgress`；仍失败时检查是否有防火墙拦截本地 2999 端口。

**对局中能看到伤害、伤害占比、承伤吗？**
不能。Live Client Data API 只提供每名玩家的 KDA、补刀、视野分、等级和装备，不提供伤害、承伤和金币（只有当前玩家自己的实时金币）。对局中只显示这些能拿到的实时指标，经济用已购装备总价近似。伤害/承伤/治疗会在**对局结束后**由战绩接口补齐，出现在「我的战绩 → 本局详情」的六边形和指标里。

**国服能用吗？**
可以。国服客户端同样是 LCU 接口，`npm run doctor` 能读到阶段和战绩即可。若客户端由 WeGame 启动，进程名仍是 `LeagueClientUx.exe`。

**会影响游戏或封号吗？**
只读本地客户端接口，不注入游戏进程、不修改客户端文件、不自动操作对局。和常见战绩查询工具原理相同。仍请自行评估风险，不要将端口/token 暴露给他人。

**评分和 OP.GG 一样吗？**
不一样。这里的参考值针对“快速识别队友状态”调过，更强调分均伤害、参团和稳定性；不包含对局内视野布置、控制时长等更细的数据。

**为什么有人评分高但坑指数也高？**
评分看“数据完成度”，坑指数看“是否明显低于同位置基准”。比如刷了很多伤害但场均死亡 10 次、参团 25%，可能评分不低但坑指数偏高。
